# NEED_CLARIFICATION: Removed Version/Status/Last Updated Blocks

## 1. Context & Trigger
During documentation repair, body-level metadata blocks (`**Version:**`, `**Status:**`, `**Last Updated:**`, `**Audience:**`) were removed in favor of Git VCS metadata and standard frontmatter.

## 2. Unresolved Question
Whether historical document version metadata should be retained in file bodies or tracked exclusively via VCS and frontmatter.

## 3. Options Considered
### Option A: Retain in Body
- Pros: Visible in raw file text without Git.
- Cons: Drifts from real revisions, violates clean frontmatter rules.

### Option B: Rely on Git VCS and Canonical Docs System
- Pros: Single source of truth in VCS history.
- Cons: Requires git blame/log to view historic audit stamps.

## 4. Resolution & Decision
- **Selected Option**: Option B
- **Decision Rationale**: Git is the authoritative version store and docs are continuously maintained. Removed legacy blocks are archived in documentation history.
- **Decided By**: Enterprise Architecture Team
- **Date Decided**: 2026-10-13
