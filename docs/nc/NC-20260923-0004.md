# NEED_CLARIFICATION: Document Kind Assignments

## 1. Context & Trigger
Assignment of `kind` frontmatter enum values (`blueprint`, `contract`, `cross-cutting`, `operational`) to legacy documentation files.

## 2. Unresolved Question
Classification boundaries for documents like future-features (blueprint) and glossary (cross-cutting).

## 3. Options Considered
### Option A: Standardized 4-Kind Taxonomy
- Pros: Clean, consistent indexing across `docs/INDEX.md`.
- Cons: Minor taxonomy generalization.

### Option B: Custom kind enums
- Pros: Precise per-file labeling.
- Cons: Fragments taxonomy schema.

## 4. Resolution & Decision
- **Selected Option**: Option A
- **Decision Rationale**: Conforms to standard 4-kind docs taxonomy and ensures uniform index traversal.
- **Decided By**: Documentation Governance
- **Date Decided**: 2026-10-13
- **Associated ADR**: docs/adr/0001-monorepo-nx-orchestration-and-enterprise-governance.md
