# 2. Product Components

## 2.1 Razor Engine

The Engine is a single, headless binary that serves both developers and production users. There is no separate "DevEngine" build. The same executable is deployed everywhere, with capabilities gated entirely by the license and permissions issued by Razor Cloud after authentication.

**Key characteristics:**

- **Headless operation** – After authentication, the Engine displays a live log stream and writes rotating daily log files to a local `logs/` directory. It provides no interactive CLI, menu, or local command interface. All interactions happen through Razor Cloud.
- **Stateless execution node** – The Engine holds no long‑term configuration, schedule, or business logic. It receives commands (run backtest, start live, inject genes, etc.) along with all required configuration from the Cloud, executes them, and streams results back. The Cloud is the single source of truth.
- **Task‑oriented architecture** – From v2.0.0 LTS, the Engine will support concurrent operations (e.g., running a live trading session while executing an optimisation). Each operation is isolated with its own clock, broker instance, and data context.
- **Platform support** – Windows (x64) and Linux (Debian/Ubuntu, x64).

**Bootstrap configuration** – The Engine requires no configuration file. Credentials are provided either interactively at startup or via the `--auth` command‑line flag (`--auth=username,password,apikey`). All operational parameters (strategy specs, execution specs, timeframes, symbols, etc.) are pushed from the Cloud per command. Credentials are held in memory only and never persisted to disk.

**Authentication options:**
- **Interactive prompt** – The Engine prompts for Cloud Username, Cloud Password, and Instance API Key on startup.
- **Command‑line flag** – For automation and service deployment, the `--auth` flag accepts three comma‑separated values.
- **Environment variable** – The `RAZOR_AUTH_TOKEN` environment variable can be set to a base64‑encoded string of `username:password:apikey`.

## 2.2 Razor Cloud

Razor Cloud is the web‑based control plane and dashboard. It is the **sole interface** through which users interact with their engines, regardless of whether they are developing a strategy or running a live production instance.

**Capabilities:**

- **Instance management** – Register engines, issue and revoke API keys, monitor connectivity and health.
- **Remote command & control** – Start/stop strategies, trigger backtests, launch optimisations, inject genes, deploy extension DLLs, update engine binaries. All commands are queued and executed when the engine acknowledges.
- **Scheduling** – The Cloud holds all scheduling logic. For example, continuous optimisation runs are triggered by the Cloud based on user‑defined calendars; the engine has no timers for operational decisions.
- **Real‑time monitoring** – Live equity curves, open positions, pending orders, margin utilisation, connection status, and tick freshness.
- **Reporting & analytics** – All backtest and optimisation results are stored in the Cloud. Users generate rich reports (equity curves, metrics, trade lists, population histories) on demand or on schedule. Reports are never generated by the engine itself; the engine ships raw result data, and the Cloud renders it.
- **User & license management** – Role‑based access, subscription tracking, feature flags, instance limits.
- **Configuration management** – All strategy, execution, and optimisation configurations are created and stored in the Cloud. The engine holds no local configuration beyond the bootstrap.
- **Secrets management** – Users can store broker API keys and other secrets in the Cloud; the engine fetches them when needed via the encrypted channel.
- **Extension deployment** – Users upload or select extensions from the Marketplace, and the Cloud pushes signed DLLs to the engine.
- **Extension profile management** – Users can activate and deactivate extensions (adapters, strategies, indicators, hook plugins, NN models) per engine instance. Profiles are stored in the Cloud and pushed to the engine on connection or reload.

## 2.3 Razor Marketplace

The Marketplace is a separate service, distinct from Razor Cloud, that handles the discovery, distribution, and monetisation of extensions. It shares the same user identity system as Razor Cloud and communicates with the Cloud through secure internal APIs.

**Capabilities:**

- **Extension catalog** – Listings for free and paid extensions, including community‑developed and Razor‑curated items. Extensions can be adapters, strategies, indicators, hook plugins, neural network models, or any combination.
- **Licensing** – Respects the user's Cloud subscription and permissions. Purchases are linked to the user account.
- **Version management** – Tracks extension versions, declares compatibility with Razor SDK versions, and supports updates.
- **Distribution** – When a user acquires an extension, the Marketplace notifies Razor Cloud, which then handles deployment to the relevant engine instances.

**Monetisation** – Razor Co. charges a transaction fee on each sale occurring on the Marketplace.

## 2.4 Sdk (Public SDK)

To enable extension development without exposing engine internals, Razor Co. publishes a **public NuGet package** (`Sdk`). This package contains only the interfaces, abstract base classes, data models, and utilities required to compile an adapter, strategy, indicator, hook plugin, or neural network model. It includes no runtime implementations, no broker logic, no GA engine, and no pipeline code.

The SDK is organized into three namespaces:

- **`Sdk.Hooks`** – Hook registration interfaces (`IHookManifest`, `IHookRegistry`, `IFilterRegistration<T>`, `IActionRegistration<T>`), filter result types, and hook context interfaces for backtest, live, optimisation, and report pipelines.
- **`Sdk.Slots`** – Capability interfaces for the three slot types: `IAdapterCapability`, `IStrategyCapability`, and `INeuralNetworkModel`.
- **`Sdk.Shared`** – Domain types (`Tick`, `Position`, `Order`, `TimeFrame`, `SymbolProperties`, etc.), enums, exceptions, helpers, and base classes (`Indicator`, `StrategyBase`).

The package is proprietary but freely redistributable. It may be open‑sourced at a later stage.

**Extension types supported:**

| Extension Type | Interface / Base Class | Directory |
|----------------|------------------------|-----------|
| Adapter | `IAdapterCapability` | `Adapters/` |
| Strategy | `IStrategyCapability` (or `StrategyBase`) | `Strategies/` |
| Indicator | `Indicator` (abstract base) | `Indicators/` |
| Hook Plugin | `IHookManifest` | `Plugins/` (any scanned directory) |
| Neural Network Model | `INeuralNetworkModel` | `NeuralNetworks/` |

**Versioning:** Every extension assembly must declare the target SDK version using `[assembly: SdkVersion("1.0.0")]`. The engine validates this version before loading any assembly.
