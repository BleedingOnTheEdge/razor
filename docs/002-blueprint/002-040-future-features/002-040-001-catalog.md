# Planned Features

Razor's planned features beyond v1.0.0 LTS, grouped by area to guide long-term development. They
are listed for consideration; **none is a commitment to a specific release.**

Every feature below is expressed through the hooks-and-slots architecture rather than a bespoke
plugin type. Where a feature names a hook it registers on, that hook is the extension point; where
it names a slot capability, it is implemented as that kind of extension.

## Trading and Execution

- **Smart Order Routing (SOR)** - a meta-adapter that routes orders across multiple brokers based
  on best bid/ask. Implemented as an `IAdapterCapability` that aggregates child adapters.
- **Iceberg / Hidden Orders** - randomise large orders into smaller market slices. Exposed as hook
  plugins that register on `backtest.order.before_execute` and `live.order.before_send`, splitting
  volume and scheduling slices.
- **TWAP / VWAP Execution Algorithms** - built-in execution strategies triggered by strategy order
  parameters. Hook plugins can register on the execution hooks to implement custom slicing logic.
- **Post-Only Limit Orders** - flag orders to guarantee maker rebates, cancelling or re-pricing if
  they would cross the spread. Implemented as an order parameter respected by the adapter.
- **Local Order Book SL/TP** - maintain stop-loss/take-profit levels engine-side and fire market
  orders when triggered. Hook plugins on `backtest.position.sl_tp_check` (a proposed hook point)
  can implement trailing stops.
- **Cross-Margin Portfolio Sizing** - size positions based on total portfolio risk rather than
  isolated symbol equity. Hook plugins on `backtest.order.validation` or
  `live.order.validation` can enforce portfolio-level risk limits.
- **Kill-Switch Triggers** - global equity drop thresholds that instantly liquidate and disconnect
  adapters. Implemented as a hook plugin with action hooks on `live.equity.changed`.
- **OCO (One-Cancels-Other) Orders** - link a stop-loss and a limit order so that filling one
  cancels the other. Implemented by the broker or through adapter logic.
- **Trailing Stops** - a dynamic stop-loss that moves with the price. A hook plugin on
  `backtest.tick.after` modifies the stop-loss on open positions.
- **Bracket Orders** - entry, stop-loss and take-profit combined into an atomic group.
- **Multi-Leg Orders** - support spread trading, pairs trading, and other multi-instrument orders.
- **Partial Fills Simulation** - realistic fill simulation that takes order-book depth into
  account.
- **Market Impact Models** - slippage models that adjust for order size relative to available
  liquidity. Implemented within the adapter's `IMarketCalculator`.

## Risk and Compliance

- **Value at Risk (VaR) Modelling** - historical and parametric VaR calculated in real time during
  live trading. A hook plugin on `live.equity.changed` and `live.tick.processed`.
- **Audit Trail Logging** - immutable, write-only logs of every broker API request for regulatory
  compliance. A hook plugin on `live.order.executed` and `live.order.rejected`.
- **Fat-Finger Limits** - hard-coded maximum order sizes that override any strategy request. A
  hook plugin on `backtest.order.validation` / `live.order.validation`.
- **Margin Call Predictive Alerts** - notify by email or chat if the current drawdown trajectory
  will hit stop-out within an hour. A hook plugin on `live.equity.changed`.
- **Wash Trading Prevention** - reject orders that would execute against the strategy's own
  resting limit orders. A hook plugin on `live.order.validation`.

## Data, Analytics and Research

- **L2/L3 Order Book Replay** - support `DepthTick` structs for DOM-based backtesting. Adapters
  with depth support register additional tick types.
- **Footprint / Volume Profile Generation** - synthesise volume profiles locally from raw ticks.
  Implemented as indicators.
- **Synthetic Spread Symbols** - define virtual symbols (for example `EURUSD-GBPUSD`) that
  generate synthetic ticks. Implemented as a specialised indicator.
- **Walk-Forward 3D Surface Plots** - export JSON for Plotly.js to render 3D optimisation
  landscapes. A hook plugin on `optimization.generation.completed`.
- **Trade Correlation Matrix** - show overlapping exposure times between strategies and symbols
  after a backtest. A hook plugin on `backtest.completed`.
- **Slippage Heatmaps** - track expected slippage by time of day and volume. A hook plugin on
  `backtest.order.after_execute`.
- **Custom Tick Synthesizer Profiles** - user-defined tick generation behaviour (random walk
  versus historical spread) for legacy bar conversion.
- **Cloud-Hosted Tick Datalake** - a central repository streaming historical memory-mapped chunks
  to engines.
- **Cloud Storage Adapters** - read historical data directly from object storage such as S3 or
  Azure Blob.
- **Multi-Exchange Data Aggregation** - a composite adapter that merges liquidity from multiple
  exchanges for a single symbol.
- **Data Quality Checks** - automatic validation for gaps, spikes and staleness before backtesting
  or live use.
- **Tick Data Compression and Streaming** - a compressed binary format that can be streamed from
  cloud storage without a full download.
- **Monte Carlo Simulation** - randomised backtest variations to assess strategy robustness.
  Cloud-orchestrated, using repeated backtest calls.
- **Sensitivity Analysis** - vary individual parameters and measure the performance impact.
  Cloud-orchestrated.
- **Custom Report Templates** - user-definable report layouts (HTML, PDF) with charts and
  statistics. Hook plugins on `report.before_generate` and `report.after_generate`.

## Machine Learning and Genetic Algorithms

- **NEAT (NeuroEvolution of Augmenting Topologies)** - evolve network structure (nodes and layers)
  alongside weights. Implemented as an `INeuralNetworkModel` slot capability; the model's
  `ParameterCount` varies per chromosome.
- **LSTM and Transformer Network Support** - recurrent topologies for time-series memory, loadable
  as `INeuralNetworkModel` implementations, likely through ONNX.
- **SHAP Value Export** - post-optimisation analysis showing which genes and parameters impacted
  fitness most. A hook plugin on `optimization.completed`.
- **Island Model GA** - multiple isolated populations run in parallel, exchanging immigrant
  chromosomes to maintain diversity. An internal optimisation enhancement.
- **Adaptive Mutation Rates (1/5th Rule)** - dynamically scale the mutation rate based on recent
  success rate. An internal optimisation enhancement; hook plugins can observe it through
  `optimization.generation.completed`.
- **Out-of-Sample Walk-Forward API** - automatically transition into out-of-sample testing after an
  anchored optimisation completes. Cloud-orchestrated: the engine's optimisation and backtest
  primitives are called in sequence.
- **Gene Constraint Dependencies** - allow one gene's `Max` to depend dynamically on another's
  current value (for example `FastPeriod < SlowPeriod`). An extension of the `[Gene]` attribute.

## Infrastructure, Operations and Observability

- **Multi-Engine Support** - run multiple isolated trading engines in the same process with
  separate configurations and telemetry.
- **Production Host Application** - a robust configurable host (console, Windows service, or
  container) with dependency injection, logging and lifecycle management.
- **Container Orchestration** - charts to spin up many headless engines for grid optimisation.
- **Web Dashboard and UI** - web-based monitoring of live trading, backtest reports and
  optimisation control. Part of Cloud.
- **Alerting and Notifications** - integrations with email, chat and other channels for critical
  events such as margin, connection loss and stop-out. Hook plugins on the `live.*` and
  `backtest.completed` action hooks.
- **Real-Time Risk Aggregation** - aggregate risk across multiple live engines in a central
  dashboard.
- **Prometheus / Grafana Exporter** - expose `CoreMetrics` through a dedicated HTTP endpoint on
  the engine. Could be a hook plugin on `backtest.tick.completed` and `live.equity.changed`.
- **Message Bus Adapter** - push events to an external bus for cross-server engine coordination. A
  hook plugin on the major hooks.
- **gRPC Control API** - multiplexed gRPC for engine-to-Cloud communication, as an alternative to
  WebSockets.
- **REST API** - expose backtesting, optimisation and live control through HTTP endpoints.
- **Hardware Intrusion Detection** - detect memory-scanning tools to protect deployed proprietary
  strategies.

## Developer Experience and SDK

- **Notebook Integration** - a Python bridge to query kernel backtests directly from a data frame.
- **F# and Python Bindings** - enable strategy development in other languages through interop or
  embedded scripting.
- **Mock Exchange Adapter** - a highly realistic local matching engine that simulates network
  latency and order-book queues. Built as a sample `IAdapterCapability` implementation.
- **Indicator Composition DSL** - write `Indicators.Get("RSI(SMA(14),14)")` using a string-based
  domain language.
- **Replay Mode GUI** - a lightweight desktop tool to step through completed backtests visually.
- **Live State Serialization** - dump `LiveBroker` state to disk on shutdown and hydrate it on
  startup, so a crash recovers without re-fetching from the exchange.
- **Hook Debugging Tools** - log hook execution chains, measure callback duration, and detect
  conflicts at the same priority level.
- **Extension Validation Tool** - a CLI tool that validates an extension assembly before upload:
  SDK version, interface implementation completeness, and hook registration validity.

## Future Hook Points

These hook points are candidates for addition in future minor releases.

| Proposed Hook | Pipeline | Type | Description |
|---|---|---|---|
| `backtest.position.sl_tp_check` | Backtest | Action | Called when a tick triggers a stop-loss/take-profit check before execution. |
| `live.position.sl_tp_check` | Live | Action | Called when a tick triggers a stop-loss/take-profit check before sending to the exchange. |
| `backtest.warmup_completed` | Backtest | Action | Called when the warm-up period ends. |
| `live.connection_lost` | Live | Action | Called when the adapter disconnects. |
| `live.connection_restored` | Live | Action | Called after a successful reconnection. |
| `optimization.best_improved` | Optimisation | Action | Called when a new best fitness is found. |
